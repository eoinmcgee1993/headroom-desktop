# Security

Headroom sits between your coding agent and the model provider, so it sees
prompts, source code and the API credentials your client sends. We take reports
about it seriously.

## Reporting a vulnerability

Please do not open a public issue for a security problem.

- **Preferred:** report it privately through GitHub:
  [Security > Report a vulnerability](https://github.com/gglucass/headroom-desktop/security/advisories/new).
- **Or email** support@extraheadroom.com with "Security" in the subject.

Include what you found, how to reproduce it, and the Headroom version you
ran. We will acknowledge the report and keep you updated while we work on a
fix.

Scope: this repository (the desktop app, its installers, the auto-updater and
the runtime it installs). The compression engine is the open-source
[`headroom-ai`](https://github.com/headroomlabs-ai/headroom) package, maintained
upstream; report engine issues there as well, or to us and we will coordinate.

## Supported versions

Fixes ship in the latest stable release and the current beta. Older versions
are not patched; the in-app updater moves every install forward.

## How releases are protected

- **Signed installers.** macOS builds are signed with our Apple Developer ID and
  notarized by Apple. Windows installers are Authenticode-signed.
- **Signed updates.** Every auto-update is signed with a separate update key.
  The app refuses an update whose signature does not match the public key built
  into it (`plugins.updater.pubkey` in `src-tauri/tauri.conf.json`).
- **Build provenance.** Installers and update bundles are built by GitHub
  Actions from tagged commits in this repository, and every release after
  v0.9.26 carries a signed provenance attestation. To check that a file you
  downloaded was built here, and from which commit and workflow:

  ```sh
  gh attestation verify <downloaded-file> --repo gglucass/headroom-desktop
  ```

- **Pinned runtime downloads.** The Python runtime, the `headroom-ai` wheel and
  the bundled tools are checked against SHA-256 checksums compiled into the app
  (`src-tauri/src/tool_manager.rs`); a mismatch stops the install.
- **Hash-pinned dependencies.** Every Python dependency of the runtime is pinned
  to an exact version and to the SHA-256 of its wheels
  (`src-tauri/python/*.lock`, generated by `scripts/hash-python-locks.py`).
  pip refuses any download that does not match, and installs prebuilt wheels
  only, so no package build script runs on your machine.
- **Pinned CI.** The workflows that build and sign releases pin every action to
  a commit SHA, so a moved tag cannot run with the signing keys.
- **Dependency advisories.** CI audits the Rust, npm and Python dependency sets
  against known advisories on every change. Any advisory we accept is listed
  with its reason in `.github/workflows/test.yml`.

## Known limitations

- There has been no independent security audit or penetration test yet.
- Builds are not reproducible. Attestations show where a binary was built, not
  that rebuilding the source yields the same bytes.
- Headroom runs as your user and is not sandboxed: it has to edit your agent's
  configuration to route traffic, and as a proxy it necessarily handles your
  prompts and credentials. Code running inside it has your user's access.
- The optional MarkItDown and Serena add-ons install with unpinned
  dependencies. They are off unless you enable them.
